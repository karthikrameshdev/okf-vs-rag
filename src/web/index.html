What is Open Knowledge Format (OKF)?

The Open Knowledge Format (OKF) is an open specification introduced by Google Cloud to formalize the "LLM-wiki" pattern popularized by AI researchers like Andrej Karpathy. Instead of fragmenting knowledge into opaque vector chunks, OKF packages organizational truth as version-controlled Markdown files with standardized YAML frontmatter.

Classic Vector RAG Bottlenecks

  • Boundary Fragmentation: Arbitrary fixed-size chunking (e.g., 400 tokens) cuts sentences, lists, and code blocks mid-thought.
  • Version Staleness & Drift: Vector similarity returns deprecated legacy v1 docs alongside current v2 docs because both share high semantic embeddings.
  • Opaque Float Blobs: Stored as 768 or 3072 floating point numbers (`[0.021, -0.045, ...]`). Impossible for engineers or compliance officers to review in Git.
  • High Query Latency: Requires an embedding inference call on every query before vector ANN search can begin.
  • Multi-Hop Blindness: Cannot traverse relational links (e.g., "Find all services governed by PCI-DSS") without guessing.

Open Knowledge Format (OKF) Superpowers

  • 100% Boundary Integrity: AI agents read coherent, complete Markdown documents with zero sentence clipping.
  • Explicit Versioning & Status: YAML frontmatter enforces `status: production`, `deprecates: legacy-v1`, eliminating version hallucinations.
  • Transparent & Git-Native: 100% plain text. Can be diffed, reviewed with Pull Requests, and audited by humans in any editor.
  • Sub-Millisecond Retrieval: Instant deterministic path and tree traversal without waiting for query embedding models.
  • Deterministic Graph Traversal: Frontmatter `relations` fields allow agents to traverse directed dependency graphs deterministically.
